# configurable-keys

Objective: the browsing command keys come from a file in `~/.config/filefinder-tui` that the user edits to change them.
Branch: `feat/configurable-keys` (from `main` a271817). Delivery strategy: `exception-ok` (one commit per work unit; push, PR and merge stay the user's). Test runner: `cargo test`; lint `cargo clippy -- -D warnings`; format `cargo fmt --check`. Toolchain: `export PATH="$(brew --prefix rustup)/bin:$PATH"`.

## Specs

- **S1** (user, verbatim): "the app has keystrokes. I want the keystrokes to be in a file in .config/filefinder-tui  so that the user can change the keys by editing the file"
- **S2 Scope** (user choice, L2): "Browsing commands (Recommended)" — only the main file-browsing keys (`command_key` in `src/app.rs`: moving, selecting, changing files, looking, views, tabs, F5–F10). The places panel, preview, Quick Look, key sheet, menus, dialogs, prompts, the search and filter fields, and `,` (settings) keep their fixed keys.
- **S3 The file.** `~/.config/filefinder-tui/keys.toml` (the app's state dir; TOML per L5). On launch, when it is missing, the app writes it with every command and its default keys, under a header comment explaining the format. Read once at launch (restart to apply).
- **S4 Format** (rewritten by L5). TOML, one top-level entry per command: `name = ["key", "key"]`, or a single string `name = "key"`; `name = []` unbinds it; a command left out keeps its defaults. A key is one character (`"M"` is Shift+m, `" "` the space bar) or a name (`up down left right home end pageup pagedown enter esc tab backspace delete insert space menu f1`–`f24`), with modifiers before it joined by `-`: `ctrl-`, `alt-` (or `opt-`), `shift-` (e.g. `"ctrl-shift-z"`). Names are case-insensitive; single characters are not.
- **S5 Problems** (assumption, stated to the user; reworded by L5). An unknown command, an unknown key, keys that aren't a list of strings, or a `[section]` is skipped, naming its line (`keys.toml line 4: unknown command "foo"`): a bad key is dropped from its list, and a list whose keys are all bad keeps that command's defaults. A file that isn't valid TOML keeps every default and names the line of the syntax error. Launch shows the first problem in red, with `(and N more)`. Two always-running commands sharing a key are named too (`keys.toml: y is both copy and quit; copy wins`). An unreadable file means the defaults.
- **S6 Behaviour with the defaults** is what it is today. Where a key does different things by context, every command bound to it is tried in a fixed order and the first that applies runs (Left moves in the grid and goes to the parent elsewhere; F5–F10 run the bar's commands only while two panes show). A Shift that runs nothing falls back to the key without it, except for a plain letter and the two panes' commands (Shift+F5–F9 run nothing, as before; L6).
- **S7 Displays follow the file** (assumption, stated to the user): the `?` sheet, the function key bar's labels, the view buttons' tooltips and the "Press d again" tip show the user's keys for a command whose keys were changed, and exactly today's text for one left at its defaults.
- **S8 Docs**: README documents the file.
